# External analyst-agent proposal contract

`proposal-check` is the first agentic integration boundary. It accepts a JSON proposal generated by an external model or human analyst and validates it against a **read-only, versioned scorecard**. It does not call an LLM, verify prose truth, access customer credentials, or execute ad-platform actions.

```json
{
  "schema_version": "growth-decision-proposal/v1",
  "report_sha256": "<sha256 of exact scorecard JSON bytes>",
  "finding": "The treatment's observed contribution is higher, but the interval is inconclusive.",
  "evidence_paths": [
    "/treatment_minus_control_per_unit/contribution",
    "/contribution_effect_95pct_bootstrap_interval",
    "/plan/decision_status"
  ],
  "next_step": "human_review",
  "assumptions": ["The synthetic fixture cannot predict real customer behavior."]
}
```

The validator requires 1–10 distinct, resolving metric paths and one of `audit_sources`, `extend_experiment`, `design_followup`, or `human_review`. It pins the exact report bytes, rejects extra fields, duplicate JSON keys, missing metrics and mutation-oriented next steps. Finding text is limited to 500 characters. A reviewer should compare each sentence to the cited metric values, the experiment plan and the limitations before accepting the proposal.

To evaluate a future LLM or swarm, construct a held-out set of valid, unsupported, contradictory and overconfident proposals. Measure citation-resolution precision, factual entailment judged independently, calibration, review time saved, and whether approved follow-up experiments improve contribution profit. A model that produces many plausible recommendations but few supported decisions fails this benchmark.
